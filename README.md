> 用钱学森《工程控制论》21 章的思想框架，指导 Agent 架构设计和复杂任务执行。

## 为什么需要这个？

Agent 开发已经进入深水区。单次 LLM 调用能做的事基本摸清了边界，更难的挑战在后面——**多步推理的稳定性、多 Agent 协作的协调、长时间运行的可靠性、资源受限下的最优决策**。

这些问题控制论研究了 70 年。反馈闭环、稳定性判据、能控能观性、冗余容错、Kalman 滤波——这些不是数学装饰，而是对任何一个闭环系统都适用的硬道理。钱学森的《工程控制论》给出了完整的理论框架。

这个项目做了**系统性的翻译工作**：把控制论概念映射为 Agent 架构设计原则和任务执行策略。它不绑定任何特定框架——无论是手写 Prompt、LangChain、AutoGen、CrewAI，还是多 Agent orchestration，底下的原理是一样的。

## 这是什么

- 🎯 **15 条设计原则** — 从稳定性优先到复杂度适配，每条有 do/don't
- 🗺️ **39 条控制论→Agent 映射** — 结构/行为/策略/评估/架构五类
- ✅ **14 项执行检查清单** — 复杂任务执行前的逐项自检
- 📋 **10 种任务类型匹配** — 不同场景的适用原则和操作指导
- 📖 **21 章完整分析** — 257 个概念、166 条原则、167 条类比

## 15 条核心原则

| # | 原则 | 一句话 |
|---|------|--------|
| P1 | 稳定性优先 | 输入扰动下输出不发散——是所有质量指标的前提 |
| P2 | 反馈闭环设计 | 生成→验证→修正，关键决策链必须闭环 |
| P3 | 状态可观测 | 推理过程通过日志和中间输出完整可重构 |
| P4 | 能控性边界 | 区分可控维度（指令可调）和不可控维度（模型局限） |
| P5 | 有限时间收敛 | 设定最大步数/token/时间预算，到上限输出最佳 |
| P6 | 帕累托权衡 | 准确率/延迟/成本/安全性之间没有"全最优" |
| P7 | 模块化串联 | 检索→推理→工具→验证，模块独立设计独立评估 |
| P8 | 协调优先 | 多 Agent 全局约束优先于个体最优 |
| P9 | 冗余容错 | 关键决策≥2/3 表决，每个关键工具至少一个 fallback |
| P10 | Kalman 式估计 | 预测→观测→计算残差→加权更新信念状态 |
| P11 | 自适应参考模型 | 以理想行为为模板，偏差 e(t) 驱动策略调整 |
| P12 | 信息效率 | 上下文窗口有硬上限 C=F·log₂(1+P/N)，每步追求最大增益 |
| P13 | FSM 完备性 | 穷举 (状态×输入) 组合，不容"未定义"行为 |
| P14 | Min-Max 鲁棒 | 长链设检查点，针对最坏情况预设降级方案 |
| P15 | 复杂度适配 | 简单任务简化模型，仅超阈值时启用完整推理链 |

## 控制论→Agent 速查

| 控制论概念 | Agent 等价含义 |
|-----------|---------------|
| 传递函数 F(s) | LLM 推理链 + 工具调用组合 |
| 反馈闭环 | 生成→验证→修正循环 |
| 状态空间 | 上下文窗口 + 对话历史 |
| 阻尼比 ζ | Temperature 参数 |
| Kalman 滤波 | 推理-验证循环（预测-更新） |
| 有限自动机 | Agent 核心架构数学原型 |
| 信道容量 C | 上下文窗口信息上限 |
| Bang-Bang 控制 | 能力边界极限工具调用 |
| 极限环 | Agent 重复无效循环 |
| 冯·诺伊曼冗余 | 多路径推理投票 |
